## 2. ANALYSIS (Deep Dive)

### Core Protocol Structure

**ERC-6551 Overview:**
- EIP-6551 proposes token-bound accounts (TBAs) — smart contract wallets owned by ERC-721 NFTs
- Each NFT can have its own wallet address, enabling "account-bound" tokens
- Implementation: Registry contract deploys minimal proxies pointing to implementation

**Base Integration:**
- ERC-6551 Registry deployed on Base (same address as mainnet: 0x000000006551c19487814612e58FE06813775758)

## 3. DISTILLATION (Extraction)

### One-Sentence Summary

ERC-6551 on Base is technically viable but adoption is nascent — opportunity exists for infrastructure that makes TBAs discoverable and usable.

### Key Architectural Decisions

1. **Registry-first design** — predictable address derivation without deploying
2. **Minimal proxy pattern** — cheap deployment, shared implementation
3. **ERC-721 ownership** — TBA is only as secure as the NFT

### Critical Dependencies

- ERC-721/ERC-1155 NFT standard
- Tokenbound SDK (optional but common)
- Base RPC for registry calls

### Failure Modes

- NFT owner loses key = TBA inaccessible
- Implementation bug = all TBAs of that type at risk
- Gas spikes = TBA creation becomes expensive
